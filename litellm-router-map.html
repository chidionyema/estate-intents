# Litellm Router — 360° Complete Map ## What This Is The router is the estate's LLM proxy. Every AI call from every consumer passes through it. It is the single chokepoint for: - **Route selection** — which model handles the request - **Cost control** — token efficiency + per-request ceilings - **Auth enforcement** — who can call which lane - **Audit** — every call logged with model, latency, tokens, cost - **Telemetry** — OTel traces to the collector There are **two routers**: | Router | Location | Purpose | |--------|----------|---------| | Laptop | `~/.estate/litellm-local/` | Local macOS, no cluster dependency | | Cluster | `llm.mumchimp.com` | Kubernetes, fleet-wide | The laptop router runs Claude Code's traffic so the founder's Max subscription works even when the cluster is down. --- ## Entry Points ### Laptop Router: `http://127.0.0.1:4000` | Caller | Auth Method | Lanes Used | |--------|-------------|------------| | Claude Code | `sk-ant-oat01-...` OAuth token | `claude-*` | | Voice pipeline | Groq API key (router holds) | `voice-asr`, `voice-tts` | | Agent workforce | Per-vendor keys | `default`, `fast`, `groq`, etc. | **Configuration**: `~/.claude/settings.json` → `ANTHROPIC_BASE_URL=http://127.0.0.1:4000` ### Cluster Router: `https://llm.mumchimp.com` | Caller | Auth Method | |--------|-------------| | Otto gateway | Master key / virtual keys | | Prospector | Master key | | Holmes | Master key | | Any cluster service | Master key | --- ## The Auth Model ### Laptop Router: `local_caller_auth.py` Runs as a LiteLLM `custom_auth` callback — **before every other callback**.
Request ↓ local_caller_auth.py ├─ Browser check: Origin header? → REFUSE │ Wrong Host? → REFUSE │ ├─ Keyed-lane check: │ Lane has api_key: os.environ/...? │ ├─ YES: Must present LITELLM_LAPTOP_KEY → ALLOW │ └─ NO (claude-*, ollama-*): Any caller → ALLOW │ ↓ Next callback
| Check | Refuses | Why | |-------|---------|-----| | Browser | `Origin` header present | Web pages can't spend vendor keys | | Browser | `Host != 127.0.0.1:4000` | DNS rebinding protection | | Keyed lane | No laptop router key | Only local services can use Groq/Cerebras |
**HOST MISMATCH BUG**: If something occupies port 4000, the router binds 5606. `local_caller_auth` sees `Host: 127.0.0.1:5606` and refuses all requests. Fix: kill $(lsof -t -i:4000) then restart router.

Why this exists: Measured 2026-09-13, one session sent 737k tokens × 439 calls in one hour. The hourly spend gate graded total spend, not per-call size — it didn't fire.
### 3. `efficiency_gateway.py` — 9 Token Mechanisms pre-call hook **OpenAI lanes** (MiniMax, Groq, etc.): | # | Mechanism | What it does | |---|-----------|---------------| | 1 | CacheGuardian | Detects system-prompt drift | | 2 | TokenKiller | Deduplicates identical tool result lines | | 3 | MCPAdapter | Truncates tool descriptions to 400 chars | | 4 | TokenBudgetOrchestrator | Tracks cumulative spend per session | | 5 | SoLPi | Replaces repeated large results with pointer | | 6 | DynamicContextPruning | Removes duplicate tool results | | 7 | CompactionManager | Bounds history to 60 messages | | 8 | GistingSimulator | Condenses old assistant turns | | 9 | ToolPairValidator | Drops orphaned tool messages | **Anthropic lane** (`claude-*`): All mechanisms are **APPEND-STABLE** — turn n+1 re-sends byte-identical bytes for everything turn n cached. ### 4. `anthropic_beta_passthrough.py` — Header Fix module-level Fixes two LiteLLM bugs on Anthropic provider: 1. **Beta headers** — LiteLLM allow-lists from BerriAI's GitHub, Claude Code ships newer betas 2. **Request fields** — LiteLLM drops `safeguards`, breaking Claude Code's safety classifier ### 5. `otel` — Telemetry OpenTelemetry Traces: model, latency, tokens, cost. **No content** (`turn_off_message_logging: true`). --- ## The x-api-key Bug and Fix ### The Problem
Claude Code → local_caller_auth.py (enabled) → LiteLLM (custom auth active) → DROPS x-api-key header → Anthropic ← EMPTY x-api-key → 401 missing authentication
### The Fix `llm/config.yaml` → `litellm_settings`: 
pass_through_client_api_key: true
CONFIRMED PRESENT in `llm/config.yaml` ### After the Fix
Claude Code (sk-ant-oat01-... OAuth token) → local_caller_auth.py (passes) → LiteLLM → pass_through_client_api_key: true → x-api-key FORWARDED to Anthropic → Anthropic accepts Max OAuth → 200 OK

~/.estate/litellm-local/litellm-local install
1. Copy launcher + config + modules to `~/.estate/litellm-local/` 2. Decrypt vendor keys (SOPS/age) into `secrets/` 3. Decrypt `LITELLM_LAPTOP_KEY` into `caller/` 4. Generate `config.runtime.yaml` 5. Register `com.estate.litellm-local` with launchd 6. Wait 90s for `/health/liveliness` — **fail hard if not live** ### Why Staged Outside `~/Documents` launchd agents cannot read `~/Documents` (macOS TCC restriction). `install` copies to `~/.estate/litellm-local/`, launchd runs from there. ### Commands
~/.estate/litellm-local/litellm-local status
